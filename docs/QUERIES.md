## 01 Monthly revenue, orders and growth

**Business question.** How fast is the marketplace growing month over month and year over year?

**Technique.** monthly aggregation on the star schema, LAG() for MoM and YoY growth, moving average window

<details><summary>SQL (<code>sql/analysis/01_monthly_revenue_growth.sql</code>)</summary>

```sql
WITH monthly AS (
    SELECT
        d.month_start,
        d.year_month,
        count(*)            AS orders,
        sum(o.items_value)  AS revenue
    FROM fact_orders AS o
    JOIN dim_date    AS d ON o.purchase_date_key = d.date_key
    WHERE o.is_valid_sale
      AND d.is_reporting_period
    GROUP BY d.month_start, d.year_month
)
SELECT
    year_month,
    orders,
    round(revenue, 0)                                               AS revenue_brl,
    round(revenue / orders, 2)                                      AS aov_brl,
    round(100 * (revenue / LAG(revenue) OVER w - 1), 1)             AS mom_growth_pct,
    -- LAG(.., 12) is only defined from Jan 2018 on (12 months of history needed)
    round(100 * (revenue / LAG(revenue, 12) OVER w - 1), 1)         AS yoy_growth_pct,
    round(avg(revenue) OVER (w ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 0) AS revenue_3m_avg
FROM monthly
WINDOW w AS (ORDER BY month_start)
ORDER BY month_start;
```

## 02 Year-to-date KPI comparison (Jan-Aug 2018 vs Jan-Aug 2017)

**Business question.** What do the headline KPIs look like this year versus the same period last year?

**Technique.** conditional aggregation (FILTER), like-for-like period comparison, UNPIVOT-style layout with a VALUES table

<details><summary>SQL (<code>sql/analysis/02_ytd_kpi_comparison.sql</code>)</summary>

```sql
WITH ytd AS (
    SELECT
        d.year,
        count(*)                                        AS orders,
        count(DISTINCT o.customer_key)                  AS customers,
        sum(o.items_value)                              AS revenue,
        sum(o.freight_value)                            AS freight,
        avg(o.items_value)                              AS aov,
        avg(o.items_count)                              AS items_per_order,
        avg(CASE WHEN o.is_on_time THEN 1.0 ELSE 0.0 END)
            FILTER (WHERE o.is_delivered)               AS on_time_rate,
        avg(o.delivery_days) FILTER (WHERE o.is_delivered) AS delivery_days,
        avg(o.review_score)                             AS avg_review,
        avg(CASE WHEN o.customer_order_seq > 1 THEN 1.0 ELSE 0.0 END) AS repeat_order_share
    FROM fact_orders AS o
    JOIN dim_date    AS d ON o.purchase_date_key = d.date_key
    WHERE o.is_valid_sale
      AND d.month BETWEEN 1 AND 8
      AND d.year IN (2017, 2018)
    GROUP BY d.year
), pivoted AS (
    SELECT
        k.kpi, k.sort_order,
        max(CASE WHEN y.year = 2017 THEN k.val END) AS v2017,
        max(CASE WHEN y.year = 2018 THEN k.val END) AS v2018
    FROM ytd AS y,
    LATERAL (VALUES
        (1, 'Orders',                    CAST(y.orders AS DOUBLE)),
        (2, 'Active customers',          CAST(y.customers AS DOUBLE)),
        (3, 'Revenue (BRL)',             CAST(y.revenue AS DOUBLE)),
        (4, 'Freight billed (BRL)',      CAST(y.freight AS DOUBLE)),
        (5, 'Average order value (BRL)', CAST(y.aov AS DOUBLE)),
        (6, 'Items per order',           y.items_per_order),
        (7, 'On-time delivery %',        100 * y.on_time_rate),
        (8, 'Avg delivery days',         y.delivery_days),
        (9, 'Avg review score',          y.avg_review),
        (10, 'Repeat-order share %',     100 * y.repeat_order_share)
    ) AS k(sort_order, kpi, val)
    GROUP BY k.kpi, k.sort_order
)
SELECT
    kpi,
    round(v2017, 2)                       AS jan_aug_2017,
    round(v2018, 2)                       AS jan_aug_2018,
    round(100 * (v2018 / v2017 - 1), 1)   AS change_pct
FROM pivoted
ORDER BY sort_order;
```

</details>

## 03 Monthly acquisition cohorts and retention matrix

**Business question.** Of the customers acquired in a month, what share buys again 1, 2, 3, 6 and 12 months later?

**Technique.** cohort assignment from dim_customer, date_diff in months, conditional aggregation into a matrix; cells that are not yet observable are NULL, not 0

<details><summary>SQL (<code>sql/analysis/03_cohort_retention.sql</code>)</summary>

```sql
WITH activity AS (               -- distinct (customer, month) with a valid purchase
    SELECT DISTINCT
        o.customer_key,
        d.month_start AS activity_month
    FROM fact_orders AS o
    JOIN dim_date    AS d ON o.purchase_date_key = d.date_key
    WHERE o.is_valid_sale AND d.is_reporting_period
), cohort AS (                   -- cohort = month of the customer's first ever valid purchase
    SELECT
        customer_key,
        CAST(date_trunc('month', first_purchase_date) AS DATE) AS cohort_month
    FROM dim_customer
    WHERE first_purchase_date BETWEEN DATE '2017-01-01' AND DATE '2018-08-31'
), cohort_activity AS (
    SELECT
        c.cohort_month,
        date_diff('month', c.cohort_month, a.activity_month) AS month_number,
        count(DISTINCT a.customer_key)                       AS active_customers
    FROM cohort   AS c
    JOIN activity AS a USING (customer_key)
    GROUP BY ALL
)
SELECT
    strftime(cohort_month, '%Y-%m') AS cohort,
    max(active_customers) FILTER (WHERE month_number = 0) AS cohort_size,
    -- a cell is observable only if cohort_month + k <= last complete month (2018-08)
    CASE WHEN cohort_month + INTERVAL 1 MONTH <= DATE '2018-08-01' THEN
        round(100.0 * coalesce(max(active_customers) FILTER (WHERE month_number = 1), 0)
              / max(active_customers) FILTER (WHERE month_number = 0), 2)
    END AS m1_pct,
    CASE WHEN cohort_month + INTERVAL 2 MONTH <= DATE '2018-08-01' THEN
        round(100.0 * coalesce(max(active_customers) FILTER (WHERE month_number = 2), 0)
              / max(active_customers) FILTER (WHERE month_number = 0), 2)
    END AS m2_pct,
    CASE WHEN cohort_month + INTERVAL 3 MONTH <= DATE '2018-08-01' THEN
        round(100.0 * coalesce(max(active_customers) FILTER (WHERE month_number = 3), 0)
              / max(active_customers) FILTER (WHERE month_number = 0), 2)
    END AS m3_pct,
    CASE WHEN cohort_month + INTERVAL 6 MONTH <= DATE '2018-08-01' THEN
        round(100.0 * coalesce(max(active_customers) FILTER (WHERE month_number = 6), 0)
              / max(active_customers) FILTER (WHERE month_number = 0), 2)
    END AS m6_pct,
    CASE WHEN cohort_month + INTERVAL 12 MONTH <= DATE '2018-08-01' THEN
        round(100.0 * coalesce(max(active_customers) FILTER (WHERE month_number = 12), 0)
              / max(active_customers) FILTER (WHERE month_number = 0), 2)
    END AS m12_pct
FROM cohort_activity
GROUP BY cohort_month
ORDER BY cohort_month;
```

## 04 RFM segmentation

**Business question.** Which customer segments exist by recency, frequency and monetary value, and how much revenue does each hold?

**Technique.** per-customer aggregation, NTILE(5) quintiles for Recency and Monetary, rule-based Frequency score (97% of customers buy once, so frequency quintiles would be arbitrary ties), CASE segment rules

<details><summary>SQL (<code>sql/analysis/04_rfm_segmentation.sql</code>)</summary>

```sql
WITH customer AS (
    SELECT
        o.customer_key,
        date_diff('day', CAST(max(o.purchase_ts) AS DATE), DATE '2018-09-01') AS recency_days,
        count(*)                AS frequency,
        sum(o.items_value)      AS monetary
    FROM fact_orders AS o
    JOIN dim_date    AS d ON o.purchase_date_key = d.date_key
    WHERE o.is_valid_sale AND d.is_reporting_period
    GROUP BY o.customer_key
), scored AS (
    SELECT
        *,
        NTILE(5) OVER (ORDER BY recency_days DESC, customer_key) AS r_score,  -- 5 = most recent
        NTILE(5) OVER (ORDER BY monetary ASC, customer_key)      AS m_score,  -- 5 = highest spend
        CASE WHEN frequency >= 3 THEN 5 WHEN frequency = 2 THEN 4 ELSE 1 END AS f_score
    FROM customer
), segmented AS (
    SELECT
        *,
        CASE
            WHEN f_score >= 4 AND r_score >= 4 THEN '1 Champions (repeat, recent)'
            WHEN f_score >= 4                  THEN '2 Loyal, lapsing (repeat, not recent)'
            WHEN r_score >= 4 AND m_score >= 4 THEN '3 New high-value'
            WHEN r_score >= 4                  THEN '4 New low-value'
            WHEN r_score = 3                   THEN '5 Needs attention'
            WHEN m_score >= 4                  THEN '6 At risk, high-value'
            ELSE                                    '7 Hibernating, low-value'
        END AS segment
    FROM scored
)
SELECT
    segment,
    count(*)                                                    AS customers,
    round(100.0 * count(*) / sum(count(*)) OVER (), 1)          AS customers_pct,
    round(avg(recency_days), 0)                                 AS avg_recency_days,
    round(avg(frequency), 2)                                    AS avg_orders,
    round(avg(monetary), 1)                                     AS avg_revenue_brl,
    round(100.0 * sum(monetary) / sum(sum(monetary)) OVER (), 1) AS revenue_pct
FROM segmented
GROUP BY segment
ORDER BY segment;
```

</details>

**Result**

| segment | customers | customers_pct | avg_recency_days | avg_orders | avg_revenue_brl | revenue_pct |
|---|---:|---:|---:|---:|---:|---:|

| 2 Loyal, lapsing (repeat, not recent) | 1,649 | 1.7 | 323 | 2.08 | 252.5 | 3.1 |
| 3 New high-value | 14,682 | 15.5 | 95 | 1 | 268 | 29.3 |

Repeat buyers (segments 1-2) are 3% of customers and 5.6% of revenue.

## 05 12-month customer value by acquisition cohort

**Business question.** How much revenue does a newly acquired customer generate in their first 12 months, and how much of it comes from repeat purchases?

**Technique.** cohort-based historical CLV with a fixed 12-month observation window (only cohorts with a full window: Jan-Aug 2017), first-order vs repeat split, quantiles

<details><summary>SQL (<code>sql/analysis/05_customer_lifetime_value.sql</code>)</summary>

```sql
WITH first_orders AS (
    SELECT
        c.customer_key,
        c.first_purchase_date,
        CAST(date_trunc('month', c.first_purchase_date) AS DATE) AS cohort_month
    FROM dim_customer AS c
    WHERE c.first_purchase_date BETWEEN DATE '2017-01-01' AND DATE '2017-08-31'
), window_orders AS (            -- all valid orders inside the customer's first 365 days
    SELECT
        f.customer_key,
        f.cohort_month,
        o.items_value,
        o.customer_order_seq
    FROM first_orders AS f
    JOIN fact_orders  AS o
      ON o.customer_key = f.customer_key
     AND o.is_valid_sale
     AND CAST(o.purchase_ts AS DATE) < f.first_purchase_date + INTERVAL 365 DAY
), per_customer AS (
    SELECT
        customer_key,
        cohort_month,
        sum(items_value)                                         AS value_12m,
        sum(items_value) FILTER (WHERE customer_order_seq = 1)   AS first_order_value,
        count(*)                                                 AS orders_12m
    FROM window_orders
    GROUP BY customer_key, cohort_month
)
SELECT
    strftime(cohort_month, '%Y-%m')                              AS cohort,
    count(*)                                                     AS customers,
    round(avg(first_order_value), 1)                             AS avg_first_order_brl,
    round(avg(value_12m), 1)                                     AS avg_value_12m_brl,
    round(median(value_12m), 1)                                  AS median_value_12m_brl,
    round(quantile_cont(value_12m, 0.9), 1)                      AS p90_value_12m_brl,
    round(100.0 * avg(CASE WHEN orders_12m > 1 THEN 1 ELSE 0 END), 2) AS repeat_within_12m_pct,
    round(100.0 * (sum(value_12m) - sum(first_order_value)) / sum(value_12m), 2) AS repeat_revenue_pct
FROM per_customer
GROUP BY cohort_month
ORDER BY cohort_month;
```

## 06 Delivery SLA vs customer review score

**Business question.** How does delivering early or late against the promised date affect the review score?

**Technique.** CASE bucketing of delay_days, share of 1-2 star reviews, window function for the share of orders per bucket

<details><summary>SQL (<code>sql/analysis/06_delivery_delay_vs_review.sql</code>)</summary>

```sql
WITH delivered AS (
    SELECT
        o.delay_days,
        o.review_score,
        CASE
            WHEN o.delay_days <= -15 THEN '1 early 15+ days'
            WHEN o.delay_days <= -8  THEN '2 early 8-14 days'
            WHEN o.delay_days <= -1  THEN '3 early 1-7 days'
            WHEN o.delay_days = 0    THEN '4 on the estimated day'
            WHEN o.delay_days <= 3   THEN '5 late 1-3 days'
            WHEN o.delay_days <= 7   THEN '6 late 4-7 days'
            WHEN o.delay_days <= 14  THEN '7 late 8-14 days'
            ELSE                          '8 late 15+ days'
        END AS delay_bucket
    FROM fact_orders AS o
    JOIN dim_date    AS d ON o.purchase_date_key = d.date_key
    WHERE o.is_delivered
      AND o.review_score IS NOT NULL
      AND d.is_reporting_period
)
SELECT
    delay_bucket,
    count(*)                                                       AS orders,
    round(100.0 * count(*) / sum(count(*)) OVER (), 1)             AS orders_pct,
    round(avg(review_score), 2)                                    AS avg_review,
    round(100.0 * avg(CASE WHEN review_score <= 2 THEN 1 ELSE 0 END), 1) AS negative_review_pct,
    round(100.0 * avg(CASE WHEN review_score = 5 THEN 1 ELSE 0 END), 1)  AS five_star_pct,
    -- share of ALL negative reviews that fall in this bucket
    round(100.0 * count(*) FILTER (WHERE review_score <= 2)
          / sum(count(*) FILTER (WHERE review_score <= 2)) OVER (), 1)   AS share_of_all_negative_pct
FROM delivered
GROUP BY delay_bucket
ORDER BY delay_bucket;
```

## 08 Seller revenue concentration (Pareto / 80-20)

**Business question.** How concentrated is revenue across sellers - what share of sellers generates 80% of revenue?

**Technique.** per-seller revenue, NTILE(10) deciles, running SUM() OVER for cumulative share

<details><summary>SQL (<code>sql/analysis/08_seller_pareto.sql</code>)</summary>

```sql
WITH seller_revenue AS (
    SELECT
        f.seller_key,
        sum(f.price)                AS revenue,
        count(DISTINCT f.order_id)  AS orders
    FROM fact_order_items AS f
    JOIN dim_date         AS d ON f.purchase_date_key = d.date_key
    WHERE f.is_valid_sale AND d.is_reporting_period
    GROUP BY f.seller_key
), ranked AS (
    SELECT
        *,
        NTILE(10) OVER (ORDER BY revenue DESC, seller_key) AS decile
    FROM seller_revenue
), by_decile AS (
    SELECT
        decile,
        count(*)            AS sellers,
        sum(revenue)        AS revenue,
        sum(orders)         AS orders,
        min(revenue)        AS min_seller_revenue
    FROM ranked
    GROUP BY decile
)
SELECT
    decile                                                             AS seller_decile,
    sellers,
    round(revenue, 0)                                                  AS revenue_brl,
    round(100.0 * revenue / sum(revenue) OVER (), 1)                   AS revenue_pct,
    round(100.0 * sum(revenue) OVER (ORDER BY decile) / sum(revenue) OVER (), 1) AS cumulative_revenue_pct,
    round(min_seller_revenue, 0)                                       AS min_seller_revenue_brl
FROM by_decile
ORDER BY decile;
```

## 11 Cross-category basket pairs (market-basket support and lift)

**Business question.** Which categories are bought together in the same order, and is the association stronger than chance?

**Technique.** self-join of distinct (order, category) pairs with a < b to avoid duplicates, support / confidence / lift computed in SQL *Note: lift = P(A and B) / (P(A) * P(B)); lift < 1 means the pair co-occurs less often than if purchases were independent*

<details><summary>SQL (<code>sql/analysis/11_category_pairs.sql</code>)</summary>

```sql
WITH order_category AS (
    SELECT DISTINCT f.order_id, p.category
    FROM fact_order_items AS f
    JOIN dim_product      AS p ON f.product_key = p.product_key
    JOIN dim_date         AS d ON f.purchase_date_key = d.date_key
    WHERE f.is_valid_sale AND d.is_reporting_period AND p.category <> 'unknown'
), n AS (
    SELECT count(DISTINCT order_id) AS total_orders FROM order_category
), cat AS (
    SELECT category, count(*) AS orders FROM order_category GROUP BY category
), pairs AS (
    SELECT a.category AS category_a, b.category AS category_b, count(*) AS orders_together
    FROM order_category AS a
    JOIN order_category AS b ON a.order_id = b.order_id AND a.category < b.category
    GROUP BY 1, 2
)
SELECT
    p.category_a,
    p.category_b,
    p.orders_together,
    round(100.0 * p.orders_together / n.total_orders, 3)                     AS support_pct,
    round(100.0 * p.orders_together / ca.orders, 2)                          AS confidence_a_to_b_pct,
    round(p.orders_together * n.total_orders / (ca.orders * cb.orders * 1.0), 2) AS lift
FROM pairs AS p
CROSS JOIN n
JOIN cat AS ca ON ca.category = p.category_a
JOIN cat AS cb ON cb.category = p.category_b
WHERE p.orders_together >= 10          -- minimum support: avoid lift on tiny counts
ORDER BY p.orders_together DESC, p.category_a, p.category_b
LIMIT 10;
```

</details>

**Result**

| bed_bath_table | home_confort | 43 | 0.04 | 0.46 | 1.11 |
| furniture_decor | housewares | 24 | 0.03 | 0.38 | 0.06 |

**Insight.** Cross-category co-purchases are rare: the most frequent pair (bed_bath_table + furniture_decor) appears in 68 orders, 0.07% of all orders, and almost every pair has lift below 1 because about 99% of orders are single-category. ## 14 Daily revenue anomaly flags

**Business question.** Which days had revenue far outside the recent normal range (promotions, outages, data gaps)?

**Technique.** daily series on dim_date (days without sales kept as 0 via LEFT JOIN), trailing 28-day mean and standard deviation that exclude the current day, z-score flag |z| > 3

<details><summary>SQL (<code>sql/analysis/14_anomaly_flags.sql</code>)</summary>

```sql
WITH daily AS (
    SELECT
        d.date,
        d.weekday_name,
        coalesce(sum(o.items_value), 0) AS revenue,
        count(o.order_id)               AS orders
    FROM dim_date AS d
    LEFT JOIN fact_orders AS o
           ON o.purchase_date_key = d.date_key AND o.is_valid_sale
    WHERE d.is_reporting_period
    GROUP BY d.date, d.weekday_name
), stats AS (
    SELECT
        *,
        avg(revenue)        OVER w AS mean_28d,
        stddev_samp(revenue) OVER w AS sd_28d
    FROM daily
    WINDOW w AS (ORDER BY date ROWS BETWEEN 28 PRECEDING AND 1 PRECEDING)
)
SELECT
    date,
    weekday_name,
    orders,
    round(revenue, 0)                         AS revenue_brl,
    round(mean_28d, 0)                        AS trailing_28d_mean,
    round((revenue - mean_28d) / sd_28d, 1)   AS z_score,
    CASE WHEN revenue > mean_28d THEN 'spike' ELSE 'drop' END AS flag
FROM stats
WHERE date >= DATE '2017-01-29'               -- first day with a full 28-day history
  AND abs((revenue - mean_28d) / sd_28d) > 3
ORDER BY date;
```

</details>

**Result**

| date | weekday_name | orders | revenue_brl | trailing_28d_mean | z_score | flag |
|---|---|---:|---:|---:|---:|---|
| 2017-04-06 | Thu | 95 | 23,169 | 12,374 | 3 | spike |
| 2017-07-18 | Tue | 190 | 28,238 | 14,271 | 3.2 | spike |
| 2017-08-29 | Tue | 137 | 33,756 | 17,249 | 4.3 | spike |
| 2017-11-20 | Mon | 225 | 44,235 | 21,899 | 6.5 | spike |
| 2017-11-23 | Thu | 275 | 43,564 | 23,378 | 3.5 | spike |
| 2017-11-24 | Fri | 1,166 | 152,654 | 24,154 | 18.6 | spike |
| 2018-02-26 | Mon | 293 | 43,632 | 28,563 | 3.4 | spike |

**Insight.** Seven days exceed |z| > 3 against the trailing 28-day mean, all spikes and no drops. Black Friday 2017-11-24 is the extreme outlier: BRL 152.7k, 6.3 times the trailing mean (z = 18.6), with 20 and 23 November also flagged.         f.seller_key,
```sql
        count(DISTINCT f.order_id)                                   AS orders,
        sum(f.price)                                                 AS revenue,
        avg(CASE WHEN f.is_shipped_late THEN 1.0 ELSE 0.0 END)       AS late_ship_rate,
        avg(o.review_score)                                          AS avg_review,
        avg(CASE WHEN o.review_score <= 2 THEN 1.0 ELSE 0.0 END)
            FILTER (WHERE o.review_score IS NOT NULL)                AS negative_rate
    FROM fact_order_items AS f
    JOIN fact_orders      AS o ON f.order_id = o.order_id
    JOIN dim_date         AS d ON f.purchase_date_key = d.date_key
    WHERE f.is_valid_sale AND d.is_reporting_period
      AND f.is_shipped_late IS NOT NULL
    GROUP BY f.seller_key
    HAVING count(DISTINCT f.order_id) >= 50
)
SELECT
    CASE
        WHEN late_ship_rate < 0.05 THEN '1 < 5% late'
        WHEN late_ship_rate < 0.10 THEN '2 5-10% late'
        WHEN late_ship_rate < 0.20 THEN '3 10-20% late'
        ELSE                            '4 20%+ late'
    END                                                          AS late_shipping_band,
    count(*)                                                     AS sellers,
    CAST(sum(orders) AS BIGINT)                                  AS orders,
    round(100.0 * sum(revenue) / sum(sum(revenue)) OVER (), 1)   AS revenue_pct,
    round(100.0 * sum(late_ship_rate * orders) / sum(orders), 1) AS late_ship_pct,
    round(sum(avg_review * orders) / sum(orders), 2)             AS avg_review_weighted,
    round(100.0 * sum(negative_rate * orders) / sum(orders), 1)  AS negative_review_pct
FROM seller
GROUP BY 1
ORDER BY 1;
```
